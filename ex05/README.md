# PROGRAM 5 : SIGNAL HANDLING IN LINUX

## AIM :
To demonstrate inter-process communication using Linux signals and study signal generation, handling, and process synchronization using:
• signal()
• kill()
• raise()
• alarm()
• pause()

## CONTEXT :
Inter-Process Communication (IPC) is the set of mechanisms that allow processes to communicate (using Shared memory, Pipes, Sockets, Signals) and synchronize with each other while running. 
We explore, Signal: It is a software interrupt used by the Linux operating system to notify a process that a specific event has occurred. Signals can be generated by the operating system, the user, or another process.

## LINUX SYSTEM CALLS / SIGNAL FUNCTIONS USED

| Function | Function/Purpose |
|---|---|
| `signal()` | Registers a signal handler for a specified signal. |
| `raise()` | Sends a signal to the currently executing process. |
| `getpid()` | Returns the Process ID (PID) of the current process. |

## SOME OF THE AVAILABLE SIGNALS 

| Signal | Signal Number | Purpose |
|---|---:|---|
| `SIGINT` | 2 | Interrupt signal. Normally generated when the user presses `Ctrl + C` to stop a running program. |
| `SIGTERM` | 15 | Requests a process to terminate gracefully. |
| `SIGKILL` | 9 | Immediately terminates a process and cannot be caught or ignored. |
| `SIGSTOP` | 19 | Stops a running process and cannot be caught or ignored. |
| `SIGCONT` | 18 | Continues a process that has been stopped. |
